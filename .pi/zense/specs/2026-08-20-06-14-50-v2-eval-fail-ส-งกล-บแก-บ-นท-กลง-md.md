# Spec v2: Eval FAIL → ส่งกลับแก้ + บันทึกลง md
approved: false

## Intent
ตอนนี้ zense_eval คำนวณ verdict (PASS/FAIL) แล้วใช้แค่ใน memory.jsonl และดัน phase เป็น review เสมอ ไม่สนว่าผ่านหรือไม่ — คือ grader บอก FAIL ก็ปล่อยผ่านไป review เลย อยากให้: (1) ถ้า FAIL ให้วนกลับเป็น implementation phase พร้อม escalation need-fix และ return content ที่สั่งชัดว่ากลับไปแก้แล้ว eval ใหม่ ห้ามไป review; (2) ถ้า PASS ถึงไป review ตามปกติ; (3) บันทึกผล eval (verdict + เหตุผล) ลงไฟล์ md ของ spec ด้วย (ทั้ง archive และ latest copy) เพื่อให้แต่ละเวอร์ชันมีเรื่องราว eval ครบ

## Scope
- extensions/zense-harness/

## Constraints
- spec archive เดิมเป็น append-only (ไม่เขียนทับเนื้อ spec ต้นฉบับ) — ผล eval ต้อง append เป็น section ใหม่ท้ายไฟล์ ห้ามแก้บรรทัดเดิม
- PASS ต้องยังเดินไป phase=review เหมือนเดิม
- grade.ok (subprocess exit) ยัง report ใน details ได้ แต่การตัดสินใจ phase ต้องใช้ verdict จาก OVERALL: ไม่ใช่ grade.ok
- ห้ามพังการทำงานเดิม: learn() memory, trajectory flags, report ยังคง return กลับ
- กระทบเฉพาะ zense_eval execute + state (เพิ่ม specMdPath/specJsonPath) + zense_spec execute (เก็บ path) ห้ามแตะ tool/phase อื่น

## Acceptance criteria
- [ ] C1: เมื่อ grader verdict = FAIL: state.phase กลับเป็น "implementation" (ไม่ใช่ review) และเพิ่ม escalation {kind:"need-fix", detail: <criteria ที่ fail หรือตัดสินใจไม่ผ่าน>} เข้า state.escalations *(check: rg 'need-fix|phase = "implementation"' ในบล็อก zense_eval พบ และ logic ตรวจ verdict === 'FAIL' ก่อนตั้ง phase)*
- [ ] C2: เมื่อ verdict = FAIL: content ที่ return กลับมีข้อความสั่งชัดเจนว่าให้กลับไปแก้แล้วเรียก zense_eval ใหม่ ห้ามไป review (เช่น มีคำว่า FAIL/แก้/eval ใหม่ และ isError=true) *(check: rg 'isError|FAIL|eval ใหม่|กลับไปแก้' ใน return path ของ verdict FAIL พบ)*
- [ ] C3: เมื่อ verdict = PASS: state.phase = "review" เหมือนเดิม และ return report ปกติ (ไม่ isError) *(check: rg 'phase = "review"' ยังอยู่ในบรรทัด PASS และไม่มี isError)*
- [ ] C4: details ของ zense_eval return มีฟิลด์ verdict ("PASS"|"FAIL"|"unknown") ไม่ใช่แค่ ok จาก grade.ok *(check: rg 'verdict' ใน details object ของ zense_eval return พบ)*
- [ ] C5: ผล eval (verdict + เหตุผล/grader output สรุป) ถูก append เป็น section ใหม่ (เช่น '## Eval') ต่อท้ายไฟล์ spec.md (latest copy) และไฟล์ archive .md ของเวอร์ชันนั้น โดยไม่เขียนทับเนื้อ spec ต้นฉบับ *(check: rg '## Eval|appendFileSync.*spec' ใน zense_eval พบ และตรวจไฟล์ .md หลังรันว่ามี section Eval ต่อท้ายโดยเนื้อเดิมไม่หาย)*
- [ ] C6: state เก็บ path ของ spec md/json ปัจจุบัน (specMdPath/specJsonPath หรือเทียบเท่า) เพื่อให้ zense_eval หาไฟล์ที่จะ append ได้ถูกเวอร์ชัน *(check: rg 'specMdPath|specJsonPath' ใน State interface และ zense_spec execute พบ และ zense_eval ใช้ค่านั้น)*
- [ ] C7: TypeScript compile ไม่เพิ่ม type error ใหม่ (error เดิม 2 ตัวที่มีอยู่ก่อนยังพอได้) *(check: npx tsc -p tsconfig ผ่าน โดยจำนวน error ไม่มากกว่าต้นฉบับ (2 ตัว))*

## Spec debt (human-verified only)
- parser ดึง per-criteria PASS/FAIL ออกจาก free-form grader output อาจไม่แม่น 100% (grader เขียนตามใจ) — หากต้องการ criteria-level ที่แม่นยำอาจต้องเปลี่ยน grader prompt ให้ output structured
- การ append eval section ลง archive .md เปลี่ยนไฟล์ append-only แต่เป็นการเพิ่มท้ายไม่เขียนทับ — ต้อง verify ว่าเข้าใจว่าไม่ทำลายประวัติเดิม
